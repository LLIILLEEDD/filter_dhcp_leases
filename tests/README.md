# Демонстрационная DHCP-лаборатория

Практические испытания текущего фильтра на реальных ISC dhcpd и dhclient:
изолированные Linux network namespaces, veth и отдельная база аренд.
Нужны Linux с systemd, зависимости из инструкции и sudo.

Из корня проекта:

```bash
bash tests/check.sh
sudo bash tests/run.sh all
bash tests/results.sh
```

| Сценарий | Что доказывает |
| --- | --- |
| `01-address` | DHCP-обмен, адрес клиента и активная запись сервера |
| `02-selection` | Реальное истечение короткой аренды и обработка повторных записей |
| `03-subnet` | Сохранность записей другой подсети |
| `04-safety` | Dry-run, копии, защитные отказы и сохранность исходника |
| `05-service-cycle` | Stop → обработка → start → новый DHCPACK |

Отдельный сценарий: `sudo bash tests/run.sh 05-service-cycle`.
Очистка: `sudo bash tests/cleanup.sh`. Обычно она выполняется автоматически;
снимки и журналы сохраняются в `tests/results/` и не включаются в Git.

Текущая программа выбирает активные аренды с остатком строго больше порога.
Истёкшие записи сохраняются — сценарий №2 проверяет именно это правило.
