## Проверка воспроизводимости

Создана чистая копия двух основных Python-модулей, README и `tests/`.
В неё не переносились `archive/`, старые результаты, `.tools/`, кэш
и состояние прежней лаборатории. Команда запускалась из постороннего
каталога `/tmp` по абсолютному пути к `tests/run.sh`.

Дополнительно у всех исходных shell-файлов копии были сняты executable bits:
использовались права `0644`, как после некоторых ZIP/Windows-копирований.
Точки входа вызывались через Bash. Исполняемую копию клиентского hook
лаборатория подготовила сама с правами `0700` в своём каталоге.

## Отказы и очистка

Дополнительно выполнены три реальные проверки:

1. После подготовки испорчена только лабораторная конфигурация dhcpd.
   Прогон завершился FAIL, остальные четыре сценария получили NOT_RUN.
   Namespace и собственные временные unit удалены, включая состояние failed.
2. После успешного первого сценария и появления следующего активного клиента
   процессу лаборатории отправлен SIGTERM. Общий итог остался FAIL,
   незапущенные сценарии отмечены NOT_RUN, ресурсы очищены.
3. Выполнен `01-address --keep`, просмотрены status и results.
   После этого прошли ручная и повторная очистка.

Имена и адреса физических интерфейсов хоста не использовались в настройке
лаборатории. Состояние адресов и маршрутов хоста после полного прогона
совпало с исходным. Созданных сетевых ресурсов после проверок не осталось.

## Как повторить

Из корня проекта после подготовки зависимостей:

```bash
bash tests/check.sh
sudo bash tests/run.sh all
bash tests/results.sh
```

[Подробная инструкция, зависимости и отдельные сценарии](TESTING.md).

Локальные сырые артефакты этой проверки сохранены в
`tests/results/20261017T200257Z-d5972b4c80/`: исходный `summary.json`, `console.log`, снимки,
резервные копии, `verification.json` и `additional-checks.json`.
Они исключены из Git. При новом запуске создаётся свой каталог.
