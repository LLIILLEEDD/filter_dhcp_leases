# Фильтрация DHCPv4-лиз

Рабочие файлы программы вынесены в корень. Учебные материалы, лаборатория,
прежний код и данные сохранены в `archive/`.

Программа выбирает IP по последней записи: нужная IPv4-подсеть,
`binding state active`, конечный срок и остаток **строго больше** `--hours`.
Для выбранного IP удаляется вся история. **Это не очистка истёкших лиз.**
Удаление активной аренды не отзывает адрес у клиента и требует отдельного
решения администратора перед применением в рабочей сети.

## Состав рабочей поставки

| Файл | Назначение |
| --- | --- |
| `filter_dhcp_leases.py` | CLI: анализ, отчёт, копия и запись результата |
| `dhcp_service_manager.py` | systemd, проверки dhcpd, блокировка и восстановление |
| `README.md` | Эта инструкция |

Для поставки копируй только эти три файла. `archive/`, `.git/`, кэш,
локальные базы и журналы не входят в поставку. Оба Python-файла должны
лежать рядом. Новое имя журнала по умолчанию — `./filter_dhcp_leases.log`.

Нужен Python 3.10+. Сторонних Python-зависимостей нет.
Для `--manage-service` нужны Linux, systemd, ISC dhcpd и запуск через root.
Проверки с подменой внешних команд не заменяют испытание с настоящим сервером:
до внедрения выполни лабораторный сценарий из архива.

## Размещение на сервере

Пример копирования программы; эти команды сами службу не запускают:

```bash
sudo install -d -m 0755 /opt/dhcp-lease-filter
sudo install -m 0644 filter_dhcp_leases.py dhcp_service_manager.py README.md /opt/dhcp-lease-filter/
sudo install -d -m 0700 /var/backups/dhcp-lease-filter
python3 /opt/dhcp-lease-filter/filter_dhcp_leases.py --help
```

В примерах ниже проверь путь базы, конфигурацию, подсеть и имя службы
по своему серверу. Исходная база должна оставаться в каталоге DHCP,
её не нужно копировать в `/opt/dhcp-lease-filter`.

## Предварительный просмотр

```bash
sudo python3 /opt/dhcp-lease-filter/filter_dhcp_leases.py \
  --input /var/lib/dhcp/dhcpd.leases \
  --subnet 10.201.90.0/24 --hours 24 \
  --apply --manage-service \
  --service isc-dhcp-server.service \
  --dhcp-config /etc/dhcp/dhcpd.conf \
  --dry-run --verbose
```

Dry-run не останавливает службу, не запускает внешние команды и не создаёт
файлы. Это анализ текущего снимка: при реальном применении база читается
после остановки службы, поэтому выборка может отличаться.

## Применение с управлением службой

После проверки плана:

```bash
sudo python3 /opt/dhcp-lease-filter/filter_dhcp_leases.py \
  --input /var/lib/dhcp/dhcpd.leases \
  --subnet 10.201.90.0/24 --hours 24 \
  --apply --manage-service \
  --service isc-dhcp-server.service \
  --dhcp-config /etc/dhcp/dhcpd.conf \
  --backup-dir /var/backups/dhcp-lease-filter \
  --log-file /var/log/dhcp-lease-filter.log
```

Режим требует уже работающую службу `active/running` и проверяет MainPID,
бинарник и явные абсолютные `-cf`/`-lf` процесса. Если в unit нет явного
`-lf`, программа откажется его останавливать. Настройку unit делает
администратор, сохраняя нужные интерфейсы и остальные параметры.

Порядок: блокировка → проверка конфигурации `dhcpd -t` → остановка →
проверка исходной базы `dhcpd -T` → чтение и анализ → временный файл →
проверки Python и `dhcpd -T` → копия → атомарная замена → запуск и проверка
процесса → успешный итог.

Если запуск после замены не удался, выполняется попытка остановки,
сохранения диагностической копии, восстановления исходной базы и запуска
с ней. При ошибке код остаётся `1`, даже если восстановление удалось.
При неудаче восстановления нужна ручная проверка службы и резервной копии.

## Запись отдельного результата

```bash
python3 filter_dhcp_leases.py \
  --input /path/to/dhcpd.leases \
  --output /path/to/dhcpd.filtered.leases \
  --subnet 10.201.90.0/24 \
  --backup-dir /path/to/backups \
  --log-file /path/to/filter.log
```

Без `--apply` исходник не заменяется, управление службой не выполняется.
Прежний выходной файл перезаписывается; перед записью создаётся копия
исходника. `--apply` без `--manage-service` — ручной режим: службу нужно
остановить самостоятельно, внешняя проверка dhcpd и автоматическое
восстановление не включаются.

## Параметры и результаты

| Параметр | Значение по умолчанию / назначение |
| --- | --- |
| `--input`, `-i` | `./dhcpd.leases`; для сервера указывай полный путь |
| `--output`, `-o` | `./dhcpd.filtered.leases`; несовместим с `--apply` |
| `--subnet`, `-s` | Обязательная IPv4-подсеть |
| `--hours` | `24`, положительное целое; сравнение строгое |
| `--check-date` | Без параметра — текущее UTC; формат `YYYY/MM/DD HH:MM:SS` |
| `--dry-run` | Анализ без файлов и внешних команд |
| `--verbose`, `-v` | Все последние IP подсети; иначе только выбранные |
| `--apply` | Замена исходника |
| `--manage-service` | Управление службой; только вместе с `--apply` |
| `--service` | `isc-dhcp-server.service` |
| `--dhcpd` | `/usr/sbin/dhcpd` |
| `--dhcp-config` | `/etc/dhcp/dhcpd.conf` |
| `--service-timeout` | `30` секунд на внешнюю команду; допустимо 1–300 |
| `--backup-dir` | Без параметра — рядом с исходником |
| `--log-file` | `./filter_dhcp_leases.log`; каталог должен существовать |

В отчёте отдельно показаны план и подтверждённый итог. Успешные события
`INFO` записываются в журнал, ошибки в терминале краткие, traceback —
в файле журнала обычного запуска.

Копии имеют вид `dhcpd.leases.YYYYMMDD_HHMMSS.1234abcd.bak`, время UTC.
Существующие копии не перезаписываются. Коды завершения:

- `0` — успех, включая dry-run.
- `1` — ошибка обработки, службы или восстановления.
- `2` — неверные аргументы CLI.

## Эксплуатационные границы

Поддерживается одиночный ISC DHCPv4 без chroot и playback. Failover-пара,
Kea и IPv6 не координируются. Форматы дат — `YYYY/MM/DD HH:MM:SS` и `never`.

Блокировка координирует управляемые запуски этой программы, не сторонних
писателей. Lock-файл рядом с базой намеренно сохраняется после выхода.
Не запускай параллельно ручное изменение той же базы.

Обычные права, владелец и группа сохраняются; ACL и SELinux требуют
дополнительной проверки. Ротации журнала и очистки старых копий нет.
SIGKILL, остановка WSL или питание могут помешать восстановлению.
`active/running` подтверждает процесс, но не заменяет проверку DHCPACK клиентом.
