# Фильтрация DHCPv4-лиз

Утилита командной строки для анализа базы ISC DHCPv4 и удаления записей
выбранных IP. Поддерживает предварительный просмотр, резервное копирование,
атомарную замену базы и управление службой через systemd.

**Правило выбора:** последняя запись IP находится в заданной подсети, имеет
`binding state active`, конечную дату окончания и остаток аренды **строго
больше** `--hours`. Для выбранного IP удаляются все его записи в файле.
Программа не предназначена для очистки истёкших аренд. Удаление записи
из базы не отзывает адрес у клиента.

## Параметры запуска

```text
python3 filter_dhcp_leases.py --subnet NETWORK [параметры]
```

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `-h`, `--help` | — | Показать справку и завершить работу |
| `-s`, `--subnet` | Обязателен | IPv4-подсеть, например `10.201.90.0/24` |
| `-i`, `--input` | `./dhcpd.leases` | Исходная база лиз |
| `-o`, `--output` | `./dhcpd.filtered.leases` | Отдельный результат; несовместим с `--apply` |
| `--hours` | `24` | Порог остатка аренды в часах; положительное целое |
| `--check-date` | Текущее время UTC | Время сравнения: `"YYYY/MM/DD HH:MM:SS"` |
| `--dry-run` | Выключен | Рассчитать результат без создания файлов и внешних команд |
| `-v`, `--verbose` | Выключен | Показать последние записи всех IP целевой подсети |
| `--apply` | Выключен | Заменить исходную базу вместо записи отдельного результата |
| `--backup-dir` | Каталог исходника | Каталог резервных копий; создаётся при необходимости |
| `--log-file` | `./filter_dhcp_leases.log` | Дополняемый журнал UTF-8; каталог должен существовать |
| `--manage-service` | Выключен | Остановить, проверить и запустить службу; требует `--apply` |
| `--service` | `isc-dhcp-server.service` | Полное имя systemd-службы |
| `--dhcpd` | `/usr/sbin/dhcpd` | Исполняемый файл ISC dhcpd для проверок |
| `--dhcp-config` | `/etc/dhcp/dhcpd.conf` | Конфигурация выбранного DHCP-сервера |
| `--service-timeout` | `30` | Тайм-аут каждой внешней команды, секунды: от 1 до 300 |

Без `--verbose` таблица содержит только выбранные IP. Все относительные
пути считаются от текущего каталога терминала, а не от расположения скрипта.

## Требования

- Python 3.10 или новее; сторонние Python-пакеты не нужны.
- Для `--manage-service`: Linux, systemd, ISC dhcpd и права root.
- Для управляемого применения: служба уже находится в `active/running`,
  а процесс dhcpd запущен с явными абсолютными `-cf` и `-lf`, совпадающими
  с выбранными конфигурацией и базой.

Программа рассчитана на одиночный ISC DHCPv4 без chroot и playback.
Управление Kea, IPv6 и координация failover-пары не реализованы.

## Режимы работы

| Режим | Аргументы | Результат | Управление службой |
| --- | --- | --- | --- |
| Предварительный просмотр | `--dry-run` | План без записи | Нет, даже с `--manage-service` |
| Отдельный файл | `--output PATH` или без выбора режима | Копия исходника и запись результата в другой файл | Нет |
| Ручное применение | `--apply` | Копия и атомарная замена исходника | Службу останавливает и возвращает администратор |
| Управляемое применение | `--apply --manage-service` | Проверки, копия, замена и попытка восстановления при ошибке | Программа |

### Запись отдельного результата

Обработка базы с сохранением результата в другой файл:

```bash
python3 filter_dhcp_leases.py \
  --input ./dhcpd.leases \
  --output ./dhcpd.filtered.leases \
  --subnet 10.201.90.0/24 \
  --hours 24 \
  --backup-dir ./backups
```

Исходник сохраняется. Существующий выходной файл перезаписывается;
резервируется именно исходник, а не прежний результат. Указать один
и тот же файл в `--input` и `--output` нельзя: для замены есть `--apply`.

### Предварительный просмотр рабочей базы

Перед запуском укажите пути, подсеть и имя службы своего сервера:

```bash
sudo python3 /opt/dhcp-lease-filter/filter_dhcp_leases.py \
  --input /var/lib/dhcp/dhcpd.leases \
  --subnet 10.201.90.0/24 --hours 24 \
  --apply --manage-service \
  --service isc-dhcp-server.service \
  --dhcp-config /etc/dhcp/dhcpd.conf \
  --dry-run --verbose
```

Dry-run анализирует текущий снимок и не проверяет управление службой:
нет остановки, команд `systemctl`/`dhcpd`, блокировки или записи журнала.
При реальном применении чтение происходит после остановки службы,
поэтому выборка может отличаться.

### Применение с управлением службой

После проверки плана выполните применение к рабочей базе:

```bash
sudo python3 /opt/dhcp-lease-filter/filter_dhcp_leases.py \
  --input /var/lib/dhcp/dhcpd.leases \
  --subnet 10.201.90.0/24 --hours 24 \
  --apply --manage-service \
  --service isc-dhcp-server.service \
  --dhcp-config /etc/dhcp/dhcpd.conf \
  --backup-dir /var/backups/dhcp-lease-filter \
  --log-file /var/log/dhcp-lease-filter.log
```

Порядок выполнения:

1. Захватить блокировку и проверить связь процесса с выбранной базой.
2. Проверить конфигурацию командой `dhcpd -t`.
3. Остановить службу и проверить исходную базу командой `dhcpd -T`.
4. Прочитать базу, выбрать IP и подготовить результат.
5. Записать временный файл, проверить его средствами Python и `dhcpd -T`.
6. Создать резервную копию и атомарно заменить исходник.
7. Запустить службу, проверить процесс и вывести успешный итог.

Если запуск после замены не удался, программа пытается остановить службу,
сохранить диагностическую копию, восстановить исходную базу и запустить
службу с ней. Ошибка восстановления требует ручной проверки.
Если в процессе нет явного `-lf` или `-cf`, программа откажется останавливать
службу. Настройку unit выполняет администратор с учётом остальных параметров.

`--apply` без `--manage-service` выполняет замену файла без внешних проверок
dhcpd и автоматического восстановления: службой нужно управлять самостоятельно.

## Установка на сервер

Рабочая поставка состоит из трёх файлов:

| Файл | Назначение |
| --- | --- |
| `filter_dhcp_leases.py` | Запускаемый CLI: анализ и изменение базы |
| `dhcp_service_manager.py` | Импортируемый модуль управления службой |
| `README.md` | Инструкция по запуску |

Оба Python-файла должны лежать рядом. Запускается только
`filter_dhcp_leases.py`. Архив, тесты, учебные материалы, `.git/`, локальные
базы и журналы для установки не требуются.

```bash
sudo install -d -m 0755 /opt/dhcp-lease-filter
sudo install -m 0644 filter_dhcp_leases.py dhcp_service_manager.py README.md /opt/dhcp-lease-filter/
sudo install -d -m 0700 /var/backups/dhcp-lease-filter
python3 /opt/dhcp-lease-filter/filter_dhcp_leases.py --help
```

База остаётся в каталоге DHCP-сервера; переносить её в `/opt` не требуется.
Копирование файлов не запускает программу и не меняет службу.

## Резервные копии, журнал и коды завершения

Имя копии: `dhcpd.leases.YYYYMMDD_HHMMSS.1234abcd.bak`.
Время указано в UTC, случайный суффикс снижает вероятность совпадения,
а режим открытия `xb` запрещает перезапись существующей копии.
В dry-run копии и журнал не создаются.

В обычном запуске журнал дополняется: время UTC, параметры, выбранные IP,
внешние команды, результат и ошибки с traceback. Терминал показывает
сводку, таблицу и краткие сообщения об ошибках. План удаления в таблице
ещё не подтверждает успешную запись: ориентируйся на итог и код завершения.

| Код | Значение |
| --- | --- |
| `0` | Успешное завершение, включая dry-run |
| `1` | Ошибка обработки, службы или восстановления; остаётся `1` и после успешного отката |
| `2` | Неверные аргументы командной строки |

## Ограничения эксплуатации

- Удаление активной аренды не заставляет клиента освободить адрес.
  Применение к рабочей сети требует решения администратора.
- Блокировка координирует управляемые запуски этой программы, но не
  сторонних писателей. Lock-файл рядом с базой сохраняется после выхода.
- Обычные права, владелец и группа сохраняются при замене исходника.
  Перенос ACL и контекста SELinux не реализован.
- Ротации журнала и удаления старых резервных копий нет.
- SIGKILL, остановка операционной системы или потеря питания могут прервать восстановление.
- Формат дат базы: `YYYY/MM/DD HH:MM:SS` либо `never`.
- Проверка `active/running` подтверждает процесс, а не выдачу DHCPACK клиенту.
  Автоматические тесты с подменой команд не заменяют испытание с настоящим dhcpd.
